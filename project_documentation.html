1. Socio-Economic Context & Problem Statement

1.1 The Problem: No Airfare Transparency in India

India's domestic aviation market is the 3rd largest globally by passenger volume (~150 million pax/year), yet unlike CPI (Consumer Price Index) or WPI (Wholesale Price Index), no publicly available, statistically rigorous airfare price index exists. This creates several issues:

Stakeholder Impact of Missing Index
DGCA (Directorate General of Civil Aviation) Cannot objectively monitor fare gouging or predatory pricing; relies on ad-hoc complaints
Ministry of Civil Aviation (MoCA) No data-driven input for fare cap policy decisions (e.g., the 2020-2022 COVID fare bands)
Competition Commission of India (CCI) Cannot detect coordinated carrier pricing or market abuse
Central Statistics Office (CSO/MOSPI) Airfare is a CPI component but uses proxy survey data, not real-time market prices
Consumers & Travel Agencies No benchmark to assess whether a fare is "high" or "low" relative to historical norms
Airlines No neutral industry benchmark for internal yield management comparison

1.2 Why Airfares Are Hard to Index

Unlike commodities (petrol, onions), airfares are:

  • Perishable: A seat on Flight 6E-2045 departing tomorrow is a fundamentally different product from the same seat next month
  • Dynamically priced: Revenue management systems change fares 10-50× per day per flight
  • Multi-dimensional: Price depends on route, carrier, booking class, advance purchase timing, day of week, seasonal demand, and channel (direct vs OTA)
  • Opaque: No central exchange or published price list — each fare is revealed only when a consumer searches

This means a traditional "survey the market price" approach (as used for CPI) fails completely. The APIx project solves this by:

  1. Continuous automated collection from multiple sources (scraping + APIs)
  2. Statistical cleaning with outlier detection
  3. Laspeyres-type weighted index construction following CPI methodology
  4. Advance purchase window stratification — recognizing that T+1 (walk-up) and T+45 (deep advance) are different economic products

4. The 8-Stage Statistical Pipeline

This is the intellectual core of the project. It transforms raw scraped fare observations into a publication-quality price index.

Stage 1: MAD Outlier Removal + Cell Median

Problem: Scraped fares contain noise — cached pages, promo fares, business class leaking into economy searches, data entry errors.

Method: Modified Z-score using Median Absolute Deviation (MAD):

$$M_z = \frac{0.6745 \times |x_i - \tilde{x}|}{MAD}$$

where $MAD = \text{median}(|x_i - \tilde{x}|)$ and $\tilde{x}$ is the median fare.

Any observation with $M_z > 3.5$ is flagged as an outlier and excluded. The cell median of the remaining observations becomes the cell estimate.

Output: One CellEstimate row per (route, carrier, AP window, date, source).

Stage 2: Cross-Source Reconciliation

Problem: Different sources (SerpAPI, airline direct, OTAs) report different prices for the same flight. Which do we trust?

Method: Inverse-variance weighting. Sources with historically lower variance get higher weight:

$$\hat{p}_{\text{fused}} = \frac{\sum_s w_s \cdot p_s}{\sum_s w_s} \quad \text{where} \quad w_s = \frac{1}{\sigma_s^2}$$

The variance $\sigma_s^2$ is computed from the SourceVarianceStat table, which accumulates over pipeline runs.

Stage 3: Regulatory Fare Decomposition

Problem: Total fares include airport charges, GST, UDF, and convenience fees — these are government-set, not market-driven. The index should track the airline-determined base fare only.

Method: Decompose using AERA (Airports Economic Regulatory Authority) published fixed charges:

$$\text{Base Fare} = \frac{\text{Total Fare} - F_{\text{origin}} - F_{\text{destination}}}{1 + \tau_{\text{GST}}}$$

where: - $F_{\text{origin}}, F_{\text{destination}}$ are airport-specific fixed charges (DEL: ₹500, BOM: ₹450, BLR: ₹400, HYD: ₹350, MAA: ₹350, CCU: ₹300) - $\tau_{\text{GST}} = 0.05$ (5% GST on economy class domestic flights)

Stage 4: AP-Window Elasticity Curve Fit

Problem: Understanding the fare curve as a function of advance purchase days.

Method: Log-linear regression:

$$\ln(\text{fare}) = \alpha + \beta \cdot \ln(\text{AP days})$$

A negative $\beta$ (expected) means fares decrease as booking moves further from departure. The fitted $(\alpha, \beta)$ parameters are stored in ElasticityParam for each route-date combination.

Stage 5: Missing Cell Imputation

Problem: Not every (route, AP window) cell has data on every day. Some scrapes fail, some flights don't operate.

Method: Use the Stage 4 elasticity curve to predict the missing fare:

$$\hat{p} = \exp(\alpha + \beta \cdot \ln(w))$$

where $w$ is the AP window (in days). The imputed value is flagged with is_imputed = True in RouteIndexValue.

Stage 6: Carrier Market-Share Aggregation

Problem: Different carriers have different fares. The index should reflect the market-weighted average, not just the cheapest.

Method: Weight by DGCA FY2024 domestic market share:

Carrier Weight
IndiGo (6E) 0.60
Air India (AI) 0.13
Akasa Air (QP) 0.10
Air India Express (IX) 0.07
SpiceJet (SG) 0.05
Vistara (UK) 0.05

$$\text{Route Fare} = \sum_c \text{share}_c \times \text{fare}_c$$

Stage 7: Törnqvist Chain Index

Problem: A fixed-weight Laspeyres index suffers from substitution bias. The Törnqvist index uses period-average weights.

Method: Chain-linked logarithmic index:

$$\ln\left(\frac{APIx_t}{APIx_{t-1}}\right) = \sum_{r,w} \bar{s}{r,w} \cdot \ln\left(\frac{p{r,w,t}}{p_{r,w,t-1}}\right)$$

where $\bar{s}{r,w} = \frac{s{r,w,t} + s_{r,w,t-1}}{2}$ is the average expenditure share across the two periods.

Stage 8: DGCA Back-Test Validation

Problem: How do we know the index is accurate?

Method: Compare monthly APIx averages against DGCA officially published average fares. Compute MAPE (Mean Absolute Percentage Error):

$$MAPE = \frac{1}{n} \sum \left|\frac{APIx_{\text{month}} - DGCA_{\text{month}}}{DGCA_{\text{month}}}\right| \times 100$$

Target: MAPE < 5%. Benchmarks stored in DGCABenchmark table.

Operational Index (Live)

In practice, the live system uses a simplified Laspeyres weighted index from index.py:

$$APIx_t = \frac{\sum_{i} W_i \times PR_i}{\sum_{i} W_i} \quad \text{where} \quad PR_i = \frac{\text{current fare}_i}{\text{base fare}_i} \times 100$$

This runs daily after each scrape slot. The full 8-stage pipeline (apix_pipeline.py) is designed for research-grade offline computation.

7. Scraping Infrastructure

7.1 Ethical Scraping Framework

The project implements extensive anti-abuse measures:

  1. robots.txt compliance: RobotsChecker checks each site's robots.txt (24-hour cache) before scraping
  2. Rate limiting: 5–12 second random delay between requests; 60-second pause between scrapers
  3. Anti-bot rotation: Different scrapers run in different time slots to avoid detection
  4. Stealth browser: Playwright with navigator.webdriver patches, fake plugins, random user agents/viewports, CAPTCHA detection

7.2 Scheduler Slots

Slot A (06:30 IST): SerpAPI → EaseMyTrip → Akasa Air
Slot B (12:30 IST): ClearTrip → SpiceJet → EaseMyTrip
Slot C (19:30 IST): Air India Express → IndiGo → SpiceJet

Each slot iterates over all 8 routes × 5 AP windows = 40 queries per scraper.

7.3 Data Cleaning (cleaner.py)

Per-route fare bounds validation:

Route Min (₹) Max (₹)
DEL-BOM 1,500 35,000
DEL-BLR 1,800 40,000
BLR-HYD 800 20,000
Default 500 50,000

Additional checks: base_fare > 0, total_fare >= base_fare, 0 ≤ ap_days ≤ 365.

IQR outlier filtering: For groups with ≥ 4 observations, removes items outside $[Q1 - 3 \times IQR, Q3 + 3 \times IQR]$.

Key Formulas Summary

Metric Formula
Representative Fare $\tilde{p}_{r,w,t} = \text{median}(\text{valid quotes for route } r, \text{AP window } w, \text{date } t)$
Price Relative $PR_i = \frac{p_{i,t}}{p_{i,0}} \times 100$ (base period fare = $p_{i,0}$)
APIx (Laspeyres) $APIx_t = \frac{\sum_i W_i \times PR_i}{\sum_i W_i}$
MoM Change $\Delta_{MoM} = \frac{\bar{APIx}{\text{this month}} - \bar{APIx}{\text{last month}}}{\bar{APIx}_{\text{last month}}} \times 100$
YoY Change $\Delta_{YoY} = \frac{\bar{APIx}{\text{this 7d}} - \bar{APIx}{\text{same 7d last year}}}{\bar{APIx}_{\text{same 7d last year}}} \times 100$
APIx (Törnqvist) $\ln(APIx_t/APIx_{t-1}) = \sum_{r,w} \bar{s}{r,w} \cdot \ln(p{r,w,t}/p_{r,w,t-1})$
